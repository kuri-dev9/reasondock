### 3.1.1 FastAPI 엔트리포인트 (main.py)

> **Main File:** `backend/app/main.py`
> **포트:** 8000 | **Config Name:** `app.main:app`

#### 기능 개요

FastAPI 애플리케이션 초기화, CORS 설정, 라우터 등록, 데이터베이스 테이블 자동 생성을 담당합니다.

#### 처리 흐름

```
앱 시작 (lifespan)
  → SQLAlchemy Base.metadata.create_all (테이블 자동 생성)
  → 라우터 등록 (conversations, chat, models, attachments, knowledge, rca)
  → CORS 미들웨어 설정 (origin: localhost:3000)
  → /api/health 헬스체크 엔드포인트

앱 종료
  → DB 엔진 dispose
```

#### 주요 클래스/파일

| 파일 | 역할 |
|------|------|
| `main.py` | FastAPI 앱 생성, lifespan 관리, 라우터/미들웨어 등록 |
| `config.py` | pydantic-settings 기반 환경설정 (DATABASE_URL, OLLAMA_BASE_URL, API keys) |

## 3.2 백엔드 — 대화 관리

### 3.2.1 대화 라우터 (conversations.py)

> **Main File:** `backend/app/routes/conversations.py`
> **Prefix:** `/api/conversations`

#### 기능 개요

대화방 CRUD 기능과 대화 검색, 내보내기(JSON/Markdown), 가져오기(JSON) 기능을 제공합니다.

#### 처리 흐름

```
대화 검색 (GET /search?q=)
  → Message + Conversation JOIN
  → content LIKE 또는 title LIKE 매칭
  → 매칭 위치 기준 ±40자 snippet 생성
  → 최대 50건 반환

대화 내보내기 (GET /{id}/export?format=)
  → 대화 + 메시지 로드
  → format=json: JSON 직렬화 + UTF-8 파일명 (URL-encode)
  → format=markdown: 마크다운 포맷 변환 + UTF-8 파일명

대화 가져오기 (POST /import)
  → ConversationImport 스키마 검증
  → Conversation 생성 → Message 일괄 삽입
```

#### 주요 클래스/파일

| 파일/클래스 | 역할 |
|-------------|------|

### 3.2.2 채팅 라우터 (chat.py)

> **Main File:** `backend/app/routes/chat.py`
> **Prefix:** `/api/conversations/{id}/chat`

#### 기능 개요

SSE 스트리밍 채팅 처리, 2-stage RAG 통합, 자동 제목 생성을 담당하는 핵심 모듈입니다.
LLM 호출은 직접 수행하지 않고 `services/llm.py`를 경유합니다.

#### 처리 흐름

```
채팅 요청 (POST /{id}/chat)
  → 대화 조회 (messages + attachments 선 로딩)
  → 사용자 메시지 DB 저장
  ──── RAG 파이프라인 시작 ────
  → [1단계] KnowledgeDocument 요약 로드 (status=ready, summary!=null)
  → [1단계] TF-IDF 코사인 유사도로 질문-요약 매칭 (threshold: 0.01)
  → [2단계] vector_store.search() 하이브리드 청크 검색 (최대 10건)
  → 우선 문서 청크 앞 배치 + 비우선 문서 뒤 배치 (최대 7건)
  → 우선 문서 요약을 컨텍스트에 추가
  ──── RAG 파이프라인 종료 ────
  → 첨부파일 컨텍스트 구성 (첨부 content_text[:8000])
  → 시스템 프롬프트 조합: 사용자 설정 + RAG + 첨부
  → 대화 이력 messages 배열 구성
  → services/llm.py.stream_chat() 호출 (timeout: 300s)
  → SSE로 thinking/content 토큰 전송
  → 응답 완료:
    → AI 메시지 DB 저장 (references 포함)
    → 첫 메시지인 경우 services/llm.py.chat()으로 자동 제목 생성
    → done 이벤트 전송 (title + references)
```

#### 핵심 함수

| 함수 | 역할 |
|------|------|
| `chat()` | 메인 채팅 엔드포인트 (SSE StreamingResponse) |
| `generate()` | SSE 스트리밍 제너레이터 (비동기) |
| `generate_title()` | 첫 대화 기반 자동 제목 생성 (15자 이내 한국어) |
| `_compute_summary_similarity()` | TF-IDF 코사인 유사도 기반 문서 요약 매칭 |

## 3.3 백엔드 — LLM 서비스

### 3.3.1 LLM 서비스 (services/llm.py)

> **Main File:** `backend/app/services/llm.py`

#### 기능 개요

채팅과 RCA LLM 호출의 공통 진입점입니다. `routes/chat.py`와 `routes/rca.py`는 이 모듈을 통해 LLM에 접근합니다. provider 분기, streaming/non-streaming, thinking 처리, timeout, 에러 핸들링을 일괄 관리합니다.

#### 주요 함수

| 함수 | 용도 | 호출처 |
|------|------|--------|
| `stream_chat(model, messages, options)` | 스트리밍 응답 | chat.py, rca.py |
| `chat(model, messages, options)` | non-streaming 응답 전체 반환 | chat.py (제목 생성) |

#### 에러 처리

| 에러 코드 | 조건 | 설명 |
|-----------|------|------|
| `thinking_only` | thinking 있음 + content 없음 | 모델이 추론만 하고 응답을 생성하지 않은 경우 |
| `empty_response` | eval_count=0 | 빈 응답 |
| `context_exceeded` | done_reason=length | 컨텍스트 초과 |

#### provider 분기

```python
# adapters/__init__.py
def get_adapter(model: str) -> ModelAdapter:
    if model.startswith("openai/"):    return OpenAIAdapter()
    if model.startswith("anthropic/"): return AnthropicAdapter()
    return OllamaAdapter()
```

## 3.4 백엔드 — RCA 분석

### 3.4.1 RCA 라우터 (routes/rca.py)

> **Main File:** `backend/app/routes/rca.py`
> **Prefix:** `/api/rca`

#### 기능 개요

xDR 파일 업로드, RCA Job 관리, Deterministic RCA 파이프라인 실행, LLM Explainability 생성을 담당합니다.

#### 처리 흐름

```
RCA 분석 요청 (POST /jobs)
  → xDR 파일 수신 및 임시 저장
  → RcaJob 레코드 생성 (status: queued)
  → rca/pipeline.py 호출 → summary JSON 생성
    [Deterministic Reasoning Engine]
  → rca/prompt_builder.py → LLM 프롬프트 조립
  → services/llm.py.stream_chat() 호출
    [LLM Explainability Layer]
  → RcaResult 저장 (summary_json + llm_response)
  → 결과 JSON 파일 저장, 원본 .dat 파일 경로는 RcaJob.file_path에 보관
  → conversation에 분석 결과 메시지 삽입
```

#### API 엔드포인트

| Method | Path | 설명 |
|--------|------|------|
| POST | `/api/rca/jobs` | xDR 파일 업로드 + 분석 실행 |
| GET | `/api/rca/jobs` | Job 목록 조회 |
| GET | `/api/rca/jobs/{job_id}` | Job 상태 조회 |
| GET | `/api/rca/results/{job_id}` | RCA 결과 JSON 조회 |

### 3.4.2 RCA 파이프라인 (rca/pipeline.py)

> **Main File:** `backend/app/rca/pipeline.py`

#### 기능 개요

xDR 파일에서 summary JSON을 생성하는 전체 흐름을 오케스트레이션합니다.
**LLM을 호출하지 않습니다.** LLM은 routes/rca.py에서 services/llm.py를 통해서만 호출합니다.

#### 처리 흐름

```
analyze_xdr_file(file_path)
  → rca/parser.py     : 0x1E 구분자 파싱 → ParsedXdr(records, stats)
  → rca/analyzer.py   : 집계 통계 + RCA 후보 → summary dict
  → summary dict 반환 (LLM 호출 없음)
```

| 출력 | 설명 |

### 3.4.4 RCA 분석기 (rca/analyzer.py)

> **Main File:** `backend/app/rca/analyzer.py`

#### 기능 개요

파싱된 레코드를 집계하고 Rule 기반 RCA 후보를 생성합니다.
현재 구현은 Reasoning Pipeline의 **Semantic Layer + Causal Layer 초기 단계**에 해당합니다.

#### 집계 항목

| 항목 | 설명 |
|------|------|
| 전체 KPI | 전체 시도/성공/실패/Drop 수 |
| call_type별 분류 | Attach / Service / TAU / Paging 등 |
| top_failures | 에러 코드 빈도 상위 목록 |
| 장비별 | MME_ID, eNB_ID별 실패 분포 |
| 시계열 | 시간대별 실패 패턴 |
| APN별 | APN별 실패 분포 |

#### RCA 후보 생성 규칙

| 규칙 | 조건 |
|------|------|
| TIMEOUT 폭증 | 에러 코드 900(TIMEOUT) 비율 급증 |
| MME 집중 | 특정 MME_ID에 실패 집중 |
| eNB 집중 | 특정 eNB_ID에 실패 집중 |
| S6a 인증 실패 | S6a Diameter 에러 코드 상승 |
| S11 GTP 실패 | S11 GTPv2C 에러 코드 상승 |
| NAS-EMM 이상 | EMM 에러 코드 상승 |
| 시간대 급증 | 단시간 내 실패 건수 급증 |

Detach 정상 cleanup 신호는 RCA 후보에서 제외합니다.

## 3.5 백엔드 — 지식 저장소

### 3.5.1 지식 라우터 (knowledge.py)

> **Main File:** `backend/app/routes/knowledge.py`
> **Prefix:** `/api/knowledge`

#### 기능 개요

지식 문서 업로드, 백그라운드 처리(텍스트 추출 → LLM 요약 → 청크 분할 → 인덱싱), 상태 조회, 삭제 기능을 제공합니다.

#### 처리 흐름

```
문서 업로드 (POST /upload)
  → 파일 크기 검증 (최대 20MB)
  → KnowledgeDocument 레코드 생성 (status: processing)
  → BackgroundTasks에 process_document 등록
  → 즉시 응답 반환

백그라운드 처리 (process_document)
  → file_parser.extract_text() 호출
  → 텍스트가 비어있으면 에러 상태로 전환
  → generate_summary(): Ollama /api/generate 직접 호출로 3~5문장 요약 생성
    → 모델: gemma4:26b, 입력: 텍스트 앞 4000자
  → chunker.split_text(): 500자 청크 분할 (50자 오버랩)
  → vector_store.add_chunks(): BM25+TF-IDF 인덱스에 추가
  → 상태 업데이트 (status: ready, chunk_count, summary)

문서 삭제 (DELETE /{id})
  → vector_store.delete_by_doc_id() 인덱스에서 제거
  → DB 레코드 삭제
```

### 3.5.2 검색 엔진 (vector_store.py)

> **Main File:** `backend/app/vector_store.py`
> **영속 파일:** `backend/knowledge_data/index.pkl`

#### 기능 개요

BM25 + TF-IDF 하이브리드 검색 엔진으로, 문서 청크를 인덱싱하고 질문에 대한 관련 청크를 검색합니다.

#### 처리 흐름

```
인덱스 빌드 (_rebuild_index)
  → 모든 청크를 토큰화 (정규식: [\w]+)
  → BM25Okapi 인덱스 빌드
  → TfidfVectorizer fit_transform

검색 (search)
  → BM25 스코어 계산 → 정규화 (max 기준)
  → TF-IDF 코사인 유사도 계산
  → 하이브리드 점수 = BM25 × 0.5 + TF-IDF × 0.5
  → 점수 상위 n건 반환 (threshold: 0.05)

영속화
  → chunks + doc_ids를 pickle로 저장/로드
  → 앱 시작 시 자동 로드, 변경 시 자동 저장
```

| 클래스/함수 | 역할 |
|-------------|------|
| `HybridSearch` | 싱글톤 검색 엔진 클래스 |
| `add_chunks()` | 문서 청크 인덱스 추가 |
| `search()` | BM25+TF-IDF 하이브리드 검색 |
| `delete_by_doc_id()` | 문서 ID 기준 인덱스 삭제 |

|--------|------|
